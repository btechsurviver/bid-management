About Project

Project Title

Online Auction Bid Management System

A multi-tier web application built to demonstrate core Data Structures and Operating System concepts in a practical auction software domain.

Data Structure Priority Queue
Operating System Concept Concurrency Control
Implementation Java Multithreading

Technology Stack

  • Frontend: HTML5, Vanilla CSS, JavaScript (ES6 fetch API)
  • Backend API: Python Flask REST API
  • Auction Engine: Java (Multithreaded execution, PriorityQueue, ReentrantLock)
  • Database: SQLite (Persistent storage for auctions and bids)

System Architecture & Concept Highlights

1. Priority Queue Data Structure

Each auction maintains its bids inside Java's PriorityQueue<Bid> (a binary min/max heap). The comparator orders bids by descending amount (and ascending timestamp for equal amounts). This provides O(1) time complexity for retrieving the current winning bid via peek() and O(log n) for bid insertion via add().

2. Concurrency Control & Synchronization

To handle concurrent bids from multiple user threads, the Java engine enforces mutual exclusion in the critical section using ReentrantLock in AuctionManager.java. When multiple bidder threads attempt to place bids simultaneously, only one thread executes the check-validate-insert routine at a time. This prevents race conditions and guarantees that bid increment rules remain mathematically valid under high concurrency.

Main Features

  • Auction management (creation, activation, termination)
  • Bid submission and automatic minimum increment validation
  • Java PriorityQueue for real-time highest bid retrieval
  • Multiple bidder threads for concurrent bidding simulation
  • ReentrantLock concurrency control preventing race conditions
  • Persistent SQLite database storage
  • Clean, fully responsive user interface for mobile, tablet, and desktop
